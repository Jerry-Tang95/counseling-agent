# 长期记忆设计（参考主流 Agent 的通用做法）

> 目标：让记忆“有用、可控、不过度”。不是把每句话都存下来，而是让下一次对话少重复、更连续。

## 1. 参考的行业模式

主流 Agent（ChatGPT Memory、Claude / Claude Code、Gemini Personal Context、Microsoft Copilot、Mem0、Letta / MemGPT 等）在记忆上有一些共同做法：

1. **区分短期上下文与长期记忆**
   - 当前会话用完整短期上下文；
   - 跨会话只保存稳定的用户资料和重要事实，不保存所有原文。
2. **记忆分层**
   - 用户画像 / 稳定偏好；
   - 目标、价值观、重要关系；
   - 反复出现的模式；
   - 临时事件 / 会话摘要（可过期）。
3. **写入前判断，而不是每句话都写**
   - 用户明确自述、明确要求记住 → 可写；
   - 一次性的情绪、临时状态 → 不写；
   - 敏感信息、危机细节、诊断推测 → 不自动写；
   - 冲突信息 → 更新旧记忆，不新增重复项。
4. **提取 → 合并 → 更新 / 归档**
   - 先用 LLM 判断“要不要记、记什么、和已有记忆什么关系”；
   - 服务端做去重、合并、冲突处理；
   - 不是简单 append 一堆记忆。
5. **检索按相关度 + 重要性 + 新近度**
   - 每次只注入少量最相关的记忆；
   - 不把全部记忆塞进 prompt；
   - 被使用的记忆更新 `lastUsedAt`。
6. **用户可见、可编辑、可删除**
   - 记忆管理页、逐条编辑/删除、暂停、清空；
   - 记忆默认关闭或明确 opt-in；
   - 不用于训练。

## 2. 心屿当前的写入策略

### 2.1 什么时候触发记忆整理

- 会话结束时：`SummaryAgent` 生成总结后，`MemoryAgent` 整理一次；
- 长会话中：每 **6 个用户回合**做一次增量整理；
- 用户明确说“记住/帮我记住/记一下/别忘”时：立即触发一次整理；
- 用户说“忘掉/不要记住”时：不新增记忆，并在已有记忆中查找可归档项。

### 2.2 判断矩阵

| 情况 | 处理 |
|---|---|
| 明确目标、价值观、偏好、稳定关系 | `add` / `update`，`sourceType=explicit` |
| 反复出现的模式（至少两次，或“总是/每次”） | `add`，`sourceType=inferred` |
| 一次性的情绪、临时状态、天气式闲聊 | `none`，不保存 |
| 用户明确要求记住 | 优先 `add`，但敏感内容仍拒绝 |
| 新信息与旧记忆冲突 | `update` 旧记忆，必要时 `archive` |
| 敏感身份信息、疾病诊断、药物、创伤/危机细节 | `sensitive`，不自动保存 |
| 用户说“不要记住/忘掉” | 不新增；能定位则 `archive` |

### 2.3 存储字段

`MemoryItem` 现在包含：

- `category`：目标 / 价值观 / 模式 / 重要关系 / 有效应对 / 进展 / 偏好；
- `confidence`：0–1；
- `importance`：1–5；
- `sensitivity`：`normal | sensitive`；
- `sourceType`：`explicit | inferred | summary`；
- `occurrences`：被确认/合并的次数；
- `lastConfirmedAt`、`lastUsedAt`、`expiresAt`；
- `status`：`active | archived`；
- `archivedReason`；
- 内容始终 AES-256-GCM 加密。

### 2.4 去重与冲突

- 用规范化 key（去掉“我想/我希望/能/可以”等前缀）做同义合并；
- 同一类别、相似内容的候选只更新已有记忆，不重复新增；
- 模型可返回 `update` / `archive` 操作，服务端校验 `targetId` 必须属于当前用户；
- 推断性记忆 90 天后自动过期；明确的稳定自述长期保留。

## 3. 读取策略

每次回复前：

1. 只取 `status=active` 且未过期的记忆；
2. 按 `importance × 2 + 新近度 + 关键词相关度 + 最近使用` 排序；
3. 最多取 8–10 条，注入 `MEMORY_CONTEXT`；
4. 在回复里自然引用，不逐条复述；
5. 回复完成后记录 `lastUsedAt`。

## 4. 用户控制

- 默认关闭，首次同意页单独开启；
- `/memory` 查看、编辑、删除、暂停、清空；
- 显示“出现次数 / 明确说过 / 对话推断”，让用户知道记忆来源；
- 删除会话时，同时删除由它产生的记忆；
- 不用于模型训练、广告或对外分享。

## 5. 后续可继续做的（非本次 MVP）

1. 向量检索 / embedding（当前中文用双字关键词 + 重要度 + 新近度）；
2. 记忆合成：把多条相关记忆合并成一段“用户画像”；
3. 记忆过期策略更细：按类别设置 TTL，而不是只区分 explicit/inferred；
4. 记忆审核页：会话结束后让用户确认“这次要记住什么”；
5. 用户“忘掉这个”的精确匹配和可撤销删除；
6. 记忆质量指标：重复率、引用命中率、用户删除率。
